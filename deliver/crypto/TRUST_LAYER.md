# Why Trust This Delivery Model

This is a new practice. No inherited client roster, no big-firm overhead, no extraction model. Trust is built through architecture, not claims. Every deliverable is designed to be verifiable by you - because that's the only kind of trust that matters in crypto.

This service is built for teams that need execution without surrendering operational control. The delivery model is local-first, scope-gated, proof-backed, and designed to avoid hidden custody, hidden automation, or unverified agent behavior. We do not ask for private keys, wallet custody, production treasury access, or blind trust. Every build must produce a clear acceptance command, a proof report, and an Exit Kit so the client can inspect, run, and keep the system without dependency lock-in.

## Who this is for

- Crypto founders
- Protocol operators
- Grant teams
- Hackathon teams
- AI x Web3 product teams
- Teams that need investor/demo readiness

## Why this model is credible

- Scopegate before build
- Proof report before handoff
- Exit Kit included
- Local-first default
- External access explicit and logged
- No custody of keys or funds
- Human approval required for high-risk actions
- Kill switch: one command to disconnect external services

## Exit Kit Included

Every paid tier includes an Exit Kit because the client must be able to leave with the system, not just a demo. The goal is clean ownership, not dependency lock-in.

- repo or file handoff
- run instructions
- acceptance command
- proof report
- deployment checklist
- config notes
- known limitations
- next-step recommendations
- no-custody statement
- external dependency list
